## 后续优先级

1. **拆分职责集中模块。** 检查时 `desktop/viewmodel.py` 约 1000 行，`providers/openai_compatible.py` 约 960 行。先分离界面状态/历史投影和模型设置/prompt/解析，沿用公开入口；每次拆分验证会话恢复、失败回退和前台回复路径。行数只是审查信号，不设置机械上限。
2. **减少具体实现依赖。** `application/learning_workbench.py` 直接依赖 SQLiteStore，provider 导入 `core/material_context.py` 的私有检索函数。将稳定的存储操作和公开检索接口提炼出来，再调整调用者；不为每个类添加无用途的接口层。
3. **逐步补全类型与配置。** 先覆盖 ports、后台回调、准备结果和存储返回值，再选择适合现有 Qt/provider 依赖的类型检查范围。对外服务预算和取消语义需保持一致。
4. **按职责清理风格。** 整理某模块时才格式化该模块、移除未使用导入并统一公共命名；完成一个区域后扩大相应 lint 门禁。避免格式变动掩盖行为变动。

## 验证方式

- 静态检查：`uv run --locked ruff check src tests scripts`。
- 普通回归：设置 `RUN_REAL_AI_TESTS=0` 后执行 `uv run --locked python -m pytest -q`。
- `tests/test_real_ai_guard.py` 只用合成测试验证开关，不创建 provider 或调用网络。
- `tests/test_architecture.py` 不导入 Qt 或初始化持久化；直接检查源码中的依赖。
- Mock、静态检查与离线回归不能证明真实对话质量、1 秒延迟或连续语音已达标。
