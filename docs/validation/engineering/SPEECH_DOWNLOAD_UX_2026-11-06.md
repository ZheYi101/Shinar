# 本地语音下载、内置测速与选择接线

日期：2026-11-06。基于当前工作树增量验证，保留其他任务的视觉与分发改动。普通测试显式 `RUN_REAL_AI_TESTS=0`。

## 问题与修正

原全局 busy 使所有下载按钮失效；大型卡片混合 STT/TTS，全局进度没有组件身份。改为最多 3 项独立任务、其余排队；任务提供模型、组件、阶段、字节和速度，逐项取消／续传。共享 SHA blob 和同类环境等待可取消锁，验证与计算探针通过才就绪。模型页使用固定筛选、任务区、STT/TTS 标签和紧凑详情，保留滚轮、右侧拖动条与中键滚动。

语音失败原来过于笼统。现在分别提示当前会话语言的 STT/TTS 选择、环境、测速或资源问题；TTS 失败允许 STT 与文字继续。本轮检查真实窗口对应语音缓存，只有日语实时对话 Reazon／VOICEVOX 选择，英语实时对话记录为空；SenseVoice 2025 虽已安装，旧报告仅针对中文。没有证据将这次缺英语选择归因于麦克风权限。

测速原来要求本地 WAV。新增随包 FLEURS 中英日公开示例及许可、固定版本和 hash；普通单测／配对不再弹文件选择器，录音文件成为详情中的可选入口。首次「测速并选用」完成后调用原选择逻辑；取消、失败或超速不替换配置。文件安装、环境、测速和选用继续分开显示，顶部标明当前语言／用途。

正式窗口点击还发现「设置此语言的语音模型」仅更新分类但未导航；消息与输入区两个入口均补齐 `workspace.navigate("settings")`。QML 回归实际点击按钮检查目标页面、分类与会话语言，确认不开麦、不新增历史。

## 真实本地服务

在独立测试库用已准备资产的只读文件硬链接副本验证；不复制用户选择、报告或学习数据，不作为全新环境安装通过。可见 Windows QML 点击英语 SenseVoice 2025 INT8、Melo ZH/EN 的默认测速，实际产生报告并选用，无录音文件选择器。再次通过普通 `LocalSpeechService.provider(...).bind('en')` 读入这些选择，真实识别内置英语音频并生成英语 WAV，未使用 `register_prepared`，未打开麦克风、未请求对话模型。

首轮 STT 热态 p50 380.54 ms、p95 392.61 ms；TTS 整句合成 p50 922.77 ms、p95 1096.88 ms。后续含模型冷加载的调用分别约 1980 ms 和 3948 ms，生成音频约 2.58 秒。不能把这些数据写成完整连续语音一秒通过。原始结果见 `demo-real-*/cache/reports/` 和 `live-binding.json`，实际窗口／设备状态仍需人工检查。

## 失败、修正与边界

保留早期验证失败：合成滚轮事件时间戳为 0 导致验证器第二次事件未生效，修正验证器时间戳；自定义滚动条早期未锚定右侧，已修正并复查几何。内置测速初轮出现初始化时读取尚未就绪 `shownModels.length` 的 QML 警告，已加初始化保护；第二轮设备选择验证器因异步刷新失焦失败，已在每次键盘操作前重获焦点。这些记录不能混写为 RTC、声卡或识别模型失败。

旧真实窗口下载经用户授权取消，旧界面明确确认已下载部分保留，随后重启真实 provider 程序，未自动开麦或恢复下载。当前增量不擅自更换用户模型、目标语言、`.env` 或正常学习库。真人耳机／扬声器、回声自触发、插话与设备移除门禁仍未完成；人工截图不证明它们通过。助手本轮验证付费调用为 0，不能据此推断用户自行操作窗口的调用量。

内置测速修正版已再次在空闲时重启，确认真实 provider、RTC 环境与资产就绪、麦克风关闭，停留在英语／实时对话页。实际页面明确显示英语 STT／TTS 未选用及「测速并选用」，未替用户选模型或触发真实对话。最终 wheel SHA256：`90983981852342b6c696ea8b28258923f523f89d57eee351b6a35dbd59eca026`。
