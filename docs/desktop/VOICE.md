# 分轮语音配置与验收

2026-10-30 后续增量已接入独立的连续语音入口：停顿自动提交、真实 RTC PCM、AEC 和插话取消。分轮路径继续保留；真人设备验收仍独立标记。使用、接口和证据边界见[连续语音指南](CONTINUOUS_VOICE.md)。下文描述分轮路径。

## 接口与配置

2026-10-30：桌面通过 `DesktopVoiceController` 接入 `VoiceSessionCoordinator`。Qt Multimedia 录制 16kHz、单声道 PCM16 WAV，结束录音后自动识别并提交，回复流式显示并逐句朗读。正常流程不要求再确认转写。这是自动发送的分轮过渡方案，连续收音、VAD/AEC、自然插话和 LiveKit 桌面主路径仍属后续范围。

环境配置参考仓库 `.env.example`。应用从启动目录读取 `.env`，系统环境变量优先。以下配置彼此独立，不继承 `OPENAI_*` 文本服务的凭据：

| STT 必填 | TTS 必填 |
| --- | --- |
| `LINGUALOOP_STT_BASE_URL` | `LINGUALOOP_TTS_BASE_URL` |
| `LINGUALOOP_STT_API_KEY` | `LINGUALOOP_TTS_API_KEY` |
| `LINGUALOOP_STT_MODEL` | `LINGUALOOP_TTS_MODEL` |
| — | `LINGUALOOP_TTS_VOICE` |

服务需支持 OpenAI-compatible 音频接口：STT 是 multipart `POST /audio/transcriptions`，包含 `file/model/response_format=json`，返回 `{"text":"..."}`；TTS 是 JSON `POST /audio/speech`，包含 `model/voice/input/response_format=wav`，返回 PCM WAV。使用服务文档列出的模型和 voice ID，不假设任意文本服务支持这些端点。仅填写域名时自动补 `/v1`；带路径的 API 根地址保持不变。非 localhost 地址要求 HTTPS。

配置后重新启动：

```powershell
uv sync --dev --extra desktop
uv run python scripts/check_voice_setup.py
uv run lingualoop-desktop
```

检查脚本只显示配置是否齐全及可见设备数量，不联网、不显示密钥。设置页显示语音配置状态和输入输出设备选择；显示“已配置”不代表端点实际可用。`--mock` 是离线模式，不调用真实语音。

## 使用与恢复

1. 导入或粘贴已接触过的材料，确认已读范围后直接开始自然讨论；话题与 roleplay 都不是前置条件。
2. 点击“开始语音”，点击“结束并发送”后自动识别和提交；达到 60 秒上限同样自动处理。点击取消不会识别或提交。
3. 用户消息在提交事务完成后立即显示，AI 的可见文字流进入分句合成，首段无需等待全文完成。
4. 回复生成与朗读状态分开。“停止朗读”清空播放队列并停止后续合成，文字回复继续。它不表示自然插话已经实现。
5. 设置 → 音频设备可关闭“自动朗读回复”，默认开启并独立持久化；手动朗读仍可用。STT/TTS 缺少其中一项时单独降级，文字聊天继续可用。
6. 本轮空闲后可结束并复盘。录音、识别、生成、合成或播放期间锁定业务线程；浏览材料、查看原文、访问设置及编辑下一份文字草稿仍可进行。

文字草稿与录音分别保存；已有文字草稿无需清空即可录音，语音成功或失败不会覆盖它。文字仍需手动发送，输入法组合期间 Ctrl+Enter 不提交。语音识别有误时可用下一条文字补充，不修改已发送历史。

识别失败保留临时录音供重试或丢弃；成功识别但提交验证失败时保留转写，可复制后分段用文字补充。回复失败在原用户消息下重试，使用原 turn、文本和来源，不重复发送用户消息。合成/播放失败在回复下重试朗读，完整缓存直接重播，否则只重新合成，不请求 LLM。主动停止不作为错误。

重启恢复未完成 turn 的提示，不自动调用模型；有效租约到期前不能抢占生成。旧历史没有 turn 信息时正常打开，最近回复仍可手动朗读，不补造 turn 或来源。

## 数据边界

材料发给文本服务，录音发给 STT，AI 回复发给 TTS。录音草稿不写入学习数据库。SQLite 只保存提交后的消息（语音使用 `automatic_transcript` 标记）、话题、偏好快照、反馈及复盘等业务数据；外观和新会话偏好使用 QSettings，凭据由本地环境管理。

音频放在系统临时目录 `lingualoop-audio-*`。录音读取为内存数据后删除录音文件；AI 播放文件在结束对话、切换材料、重置或正常退出时清理。强制终止/系统崩溃可能留下临时文件，可在应用退出后清理这些目录。录音重试数据在会话内存中保留，发送成功或清理会话时释放。重启恢复不会恢复未确认草稿或原始音频。

自动转写可能包含识别错误，用户可补充修正；不得只根据转写诊断发音，也不能把识别错误直接视为学习错误。材料中的指令视为内容；模型被要求只使用已提供材料中的事实，roleplay 的假设扩展要明确区分。模型可能偏离约束，仍需真实材料验收。

## 真人验收清单

配置可用服务和麦克风后，在正常 Windows 窗口执行，不能用 mock 结果替代：

- 导入实际看过的材料，确认已读范围，核对引用均在授权边界内。
- 选择自然讨论，至少三轮“说话 → 结束并发送 → 自动识别与回复 → 听到 AI 朗读”。记录是否听清、单轮延迟和是否愿意继续聊。
- 试一次取消/重录、停止/重播；临时禁用服务或断网验证错误重试不丢消息、不重复发言。
- 结束复盘，核对最多三个重点问题/复习项来自真实输出；没有足够证据时允许为空。
- 重启后恢复材料、已确认的七条或更多消息、话题、会话设置和复盘；确认临时音频已清理。

目前自动测试使用注入的合成音频与 mock STT/TTS；真实三轮语音仍是单独未完成的验收项。

## 播放、计时与工程验证

音频队列复用主线程 QMediaPlayer/QAudioOutput，按段索引使用独立临时文件。队列包含正在播放的段，最多三段且总计不超过 24 MiB；满时异步等待容量。EndOfMedia 才推进下一段，普通 StoppedState 不表示整轮结束。缓存只保留最近一份完整回复，最多 24 MiB。停止、关闭及新播放代际拒绝旧段回写。

worker 的识别、回复与合成共享长期 asyncio loop；任务 ID、会话 ID 与播放代际保护异步完成事件，不占用旧业务操作的单一回调。来源在结束录音时捕获；后续原文选择和文字草稿变化不覆盖重试上下文。

安全计时保存在运行时 `voiceController.timings`：识别完成、UI 首字/全文完成、provider 首字/全文完成、首段合成可用和播放器启动分别记录。播放器启动不等于物理扬声器已出声，Mock 延迟不能外推真实服务。验证证据见[QML 语音接线记录](../validation/engineering/VOICE_QML_2026-10-30.md)。
