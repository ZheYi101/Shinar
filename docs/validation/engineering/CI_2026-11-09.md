## 原始失败证据

提交 `210a598` 的 [Code quality 运行 42588620754](https://github.com/ZheYi101/Shinar/actions/runs/42588620754) 中，Windows／Python 3.13 通过，Windows／Python 3.11 在 `Run offline regressions` 失败。依赖安装、Ruff 和 F401 检查均通过。

[失败作业 129064424646](https://github.com/ZheYi101/Shinar/actions/runs/42588620754/job/129064424646) 的最终结果为 **1 failed, 756 passed, 11 skipped, 5 errors**，402.09 秒。错误并非安装失败或 Python 语法不兼容：

| 问题 | 触发与证据 | 修复 |
| --- | --- | --- |
| 五项阅读器用例清理失败 | fixture 先以 `asyncio.run(seed())` 建立材料准备任务，seed 循环退出后已完成／取消的任务仍归原循环所有。随后 ViewModel 的 worker 清理调用 `LearningWorkbench.aclose()`，Python 3.11 的 `asyncio.gather` 为这些已结束任务注册回调，触发 `RuntimeError: Event loop is closed` | 关闭时直接读取已完成任务的结果状态，不重新绑定回调；未完成任务仍先取消、等待实际协作清理结束，再关闭 provider 和数据库 |
| 兼容 provider 的预算回归存在调度竞态 | `test_failed_reference_attempts_are_capped_across_restart` 每轮固定等待 10ms；慢 runner 在下一轮使旧准备失效前仅进入 provider 两次，断言要求三次 | 每轮等待公开 `preparation_status` 离开 `preparing`，保留 2 秒上限及原有三次持久化预算断言；重启后的预算耗尽同时断言未创建准备工作 |

没有删除 Python 3.11 矩阵、跳过失败用例、弱化断言或关闭离线回归。
