原始速度筛选保留所有 21 项及原因在本地 `strict/stt-latency-filter.csv`；有缺失时 all_attempt_mean_ms 留空，successful_only_mean_ms 仅诊断使用。Qwen 按用户明确意见退出，不另开流式补救测试。

## VOICEVOX 的 1332 / 1703ms 到底是什么

前表“加载 / 首次推理”容易被读成两次首音；这里拆开：

| 指标 | 本机结果 | 含义 |
| --- | --- | --- |
| 新进程模型加载 | 1332ms | 模型初始化，发生在该评测进程启动时；产品常驻加载后的每句话不必重复支付，但常驻产品路径尚未交付 |
| 加载后首次首 PCM | 346ms | 第一次合成已返回第一块音频，不需等整句完成 |
| 加载后首次整句合成完成 | 1703ms | 2.016s 输出音频的全部 PCM 生成完成；不是首次出声等待 1.7s |
| 热态首 PCM 算术平均 | 447ms | 全部 12 文本共 60 次，p50 382ms、p95 765ms，最慢 1190ms |
| 两条短应答首 PCM | 平均 317ms，p95 507ms | 10 次热态样本 |

该单次冷进程“加载开始 → 首 PCM”约 1678ms，“加载开始 → 首次整句完成”约 3035ms；模型已加载则不包含这次 1332ms。以上未计 GUI、播放设备和排队。第一块 PCM 不等于已经听到声音，原音约有 117–165ms 低能量前导；立即起播的理论队列缺口 p95 457ms，需要实际设备验证是否卡顿。因此保留 VOICEVOX 是当前取舍，不宣称完整链路已过一秒。无需因误读 1703ms 就立即换模型；若预热后实际出声/连续性仍不能接受，再找日语替代。

## Melo 英文能否换声音解决

本机包的 README 明确只有一名中英混读女声。官方 sherpa 页面也说明此 ONNX 包来自 MeloTTS-Chinese，仅一个 speaker，英语还受 lexicon 覆盖限制。现有包没有可切换的美式/英式 speaker；只改音色参数不能保证消除口音和漏读。

Melo 官方独立 EN 的美式、英式、印度、澳洲和默认英语声音，以及 EN-Newest，现已分别完成 CPU / GPU 测试与双裁判回识，试听见[补测附件](./SPEECH_GPU_JAPANESE_MELO_FOLLOWUP_2026-10-29.md)。新包的回识表现优于旧中英包，但不以此直接宣称口音自然度已通过。GPU 主实验首 PCM 平均 124–177ms，CPU 2.59–3.64s；美式原始前导使理论首声约 666ms，EN-Newest 另一次共享 GPU 背景下的复测平均 434ms、最慢 3.61s，全部保留。默认声音 GPU 的一条否定句有双裁判词形偏离，五次复核与原始音频另列，尚未判定为人耳错误。Lessac 继续优先，等待用户听完新音色。

依据：[当前 ONNX 包说明](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html#vits-melo-tts-zh-en-chinese-english-1-speaker)、[Melo 官方声音范围](https://github.com/myshell-ai/MeloTTS)。

## 后续范围

1. 两版 SenseVoice GPU 补测已完成：INT8 为实际 CPU / CUDA 混合执行，速度未优于本轮同适配器 CPU 对照；2024 FP32 GPU 的主要矩阵算子在 CUDA，三语平均首字 52–58ms，作为 GPU 优先候选。精度、运行时、原始 kernel trace、准确率与资源另列，不用旧 CPU 数字冒充同条件加速比；2025 英语仍为受限备选，日语因识别质量不作可用候选。
2. 中文 TTS 使用 Melo，英语优先 Lessac，日语暂用 VOICEVOX；允许按语言、场景、STT/TTS 分别安装和保存模型。现有模型库已按 `language:scenario:task` 保存候选，不强求一个模型包覆盖全部语言；实际对话切换和常驻生命周期仍未接通。
3. 日语 STT 新增 SenseVoice 2024 FP32 GPU（58ms，CER 8.63%）、ReazonSpeech k2 v2 INT8 CPU（323ms，CER 9.11%）、Kotoba Whisper v2 FP16 GPU（346ms，CER 6.80%），均为 50×3。另有新 ORT CPU 的 2024 INT8 对照（296ms，CER 8.63%，50×1），可作不同 CPU 后端的实验候选；不覆盖旧 sherpa CPU 599ms 的淘汰结果。
4. 优先实际短句、学习者/麦克风与端点到首字、预热首音和播放连续性；保留冷启动及 p95/最慢轮次，不只看平均。
