## 实现

- 显式开启连续模式、默认 650 ms／可选 1000 ms 停顿、自动识别提交。文字草稿独立；先静音再发文字。
- Qt 主线程原始音频桥，独立 RTC/APM/VAD 进程，真实双 peer／SFU。实际声卡格式转换到 48 kHz mono PCM16；VAD 为 16 kHz 固定窗口。
- 本地近端检测负责快速插话，Engine 端点唯一切句；输入和输出代际分开，静音恢复再换麦克风代际。
- 认领版本后事务提交，续说保留来源并等待旧识别释放。取消先使持久化轮次失效，再取消推理；晚完成不能恢复旧轮。完整回复与声音交付分开。
- 播放失败保留文字生成，停止朗读只停声音，停止语音同时取消未完成回复。设备变化暂停，重连最多一次且需手动恢复监听。
- Silero v6.2.3 ONNX SHA256 `1a153a22f4509e292a94e67d6f9b85e8deb25b4988682b7e174c65279d8788e3`，MIT 许可证一同由 ModelStore 校验；基础依赖不引入 ORT。

## QML 与视觉比对

真人试用发现验收窗口每轮回复同一句日语。只读核对独立库及报告：6 条不同的确认用户消息，6 次 Mock 回复调用；根因是验证器 `SlowDialogue` 使用同一组固定回复，并未调用真实对话模型。已改为带轮次编号的三语测试句、轮换播报内容，并在聊天页明确标记 Mock；新增 20 轮唯一回复及调用次数检查。旧试用保留于本机 `desktop-08173fc8d3dd4560a3e92afda99c0887`，不能据此宣称扬声器 AEC 通过。

同次试用的 stderr 还暴露了真实设备回调错误：PySide6 6.11 的 `QAudio::State` 无法转换。静音 PCM 探针复现旧回调 0 次、新显式零参数 Qt slot 4 次；修复后连续送入 3 段静音 PCM，34560 字节只提交一次，正常排空一次、故障和回调错误均为 0，未打开麦克风。段间 Idle／Underrun 作为等待，真正 IO 错误仍暂停并反馈。此证据仅覆盖设备提交和回调，不等同真人听感或 AEC。参考 [Qt Slot](https://doc.qt.io/qtforpython-6.11/PySide6/QtCore/Slot.html) 与 [QAudioSink](https://doc.qt.io/qtforpython-6.11/PySide6/QtMultimedia/QAudioSink.html)。验证器现单独记录 Python 回调异常类型和栈位置，避免异常静默，也不记录异常正文。

对照原 `09-voice.png` 和当前暖纸界面：活动语音采用灰绿面板，状态和主按钮位置固定，静音使用独立几何 SVG；不展示模拟波形、未提供的 partial 或虚构打断状态。长草稿与错误恢复保留。

初次可见截图读取了尚未完成 polish 的旧布局，出现整页裁切；验证器改为等待窗口 exposed、实际标题栏几何稳定并重新取帧。未通过压缩正文或修改产品断点掩盖截图失败。参考 [Qt polish](https://doc.qt.io/qt-6.11/qquickitem.html#ensurePolished) 与 [Layouts](https://doc.qt.io/qt-6.11/qtquicklayouts-overview.html)。验证显式加载系统中文／日文／emoji 字体及应用内 Noto 字体。

125% 完整 30 视图通过；150% 首次在长草稿替换时失败，验证器改为等待焦点与全选完成再提交输入法事件，重跑全部 30 视图通过。两者使用 QT_SCALE_FACTOR；没有修改系统 DPI。最后一次 Mock 提示复核在 `desktop-5f02f6407eb74a36a0ed9e886bc3fdfa`，12 视图通过，QML 与 Python 回调错误均为 0。
